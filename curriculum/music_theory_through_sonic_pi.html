How the course works

Sonic Pi is the laboratory. Each lesson takes one musical idea, encodes it as data, plays it, and then asks for one change so we can hear what the change did. The programming stays deliberately ahead of the theory, and our existing skills carry the load.

This is not the Sonic Pi tutorial. That one teaches programming and uses music as the reward. Here the programming is assumed. Ruby idioms get a one-line note when they first appear and no more than that.

  • Sound first, name second. We hear an interval, a cadence, a mode before anyone tells us what it is called.
  • Music is data. A note event carries pitch, onset, duration, amplitude, and articulation. Everything else is a function over those.
  • Score and renderer stay separate. The composition is content. The playback function is interpretation. Changing one should not touch the other.
  • Every lesson ends with something worth hearing. If the last snippet in a lesson is a bare test tone, the lesson is broken.
  • Notation arrives late and on demand. We meet the staff after pitch and duration are already familiar as numbers, which turns it into a decoding exercise rather than a wall.
  • Ear training runs in parallel. Ten minutes most days, using drills we wrote ourselves, from Part 2 onwards.

Before Lesson 1

Install Sonic Pi 5.0.0 from sonic-pi.net and check that play 60 makes a noise. That is the whole setup. Headphones or decent speakers do more for progress here than any other purchase, because half of this course is hearing small differences.

Paste this into a buffer and press Run. None of it needs to make sense yet.

# Four bars that already sound like music.
# Every construct here is explained by the end of Part 3.

use_bpm 96
use_synth :pluck

# E minor pentatonic. Five notes chosen so that any order sounds intentional.
melody = [:e4, :g4, :a4, :b4, :d5, :b4, :a4, :g4]

live_loop :tune do
  melody.each do |n|
    play n, release: 0.4
    sleep 0.25          # sixteenth notes at this tempo
  end
end

live_loop :bass do
  play :e2, release: 1.8, amp: 0.7, cutoff: 70
  sleep 2               # one bass note every two beats
end

Now change one thing. Set melody to [:e4, :f4, :g4, :a4, :b4, :c5, :d5, :e5] and run it again. Same rhythm, same bass, different feeling. Working out why is roughly what Parts 2 and 5 are for.

The event model we keep refining

One representation carries the whole course. A score is a sequence of events. A renderer walks the sequence and turns each event into sound. Everything from a nursery rhyme to a two-voice invention fits this shape.

# An event is [pitch, duration_in_beats]. :r means rest.
score = [
  [:c4, 1], [:d4, 0.5], [:e4, 0.5], [:g4, 1], [:r, 1]
]

define :play_score do |score, transpose: 0, gap: 0.15|
  score.each do |pitch, dur|
    if pitch == :r
      sleep dur
    else
      # sustain most of the beat, then release. gap keeps notes from smearing.
      play pitch + transpose, sustain: dur * (1 - gap), release: dur * gap
      sleep dur
    end
  end
end

play_score score                 # as written
play_score score, transpose: 5   # up a fourth, same data

The event schema is a convention of this course. The primitives underneath it come from Sonic Pi: named notes, rings, chord and scale constructors, timed playback. Official tutorial.

The ear track

Theory we can only read is theory we cannot use. From Part 2 onwards, each part contributes a drill to a growing file called drills.rb. Run one for ten minutes on days without a lesson.

  • Part 2: pitch matching and octave recognition.
  • Part 3: clap-back rhythms and meter identification.
  • Part 4: interval recognition, ascending then harmonic.
  • Part 5: scale degree singing over a drone, mode identification.
  • Part 6: chord quality, inversion, cadence type.
  • Part 9: short melodic dictation, four notes growing to eight.

Log every session in one line: date, drill, score. After six weeks the log reports what needs practice more honestly than memory does.

Part 0. Getting a sound out

The minimum Sonic Pi needed before the music starts. Three short lessons.

Sonic Pi tutorial

1. Hello, sound

20 min
  • play, sleep, use_synth, and the Run button. That is the entire API surface for the next hour.
  • Swap :pluck for :prophet, :blade, and :fm on an unchanged phrase.
  • Find the log pane and the error messages, since we read both a lot.
Ends with: a six-note phrase we can play through four instruments by editing one word.

2. Notes are integers

25 min
  • note(:c4) returns 60. Every named pitch is an integer, so pitch arithmetic is just arithmetic.
  • Transpose by adding. Invert by subtracting from a fixed axis. Map a melody with map.
  • Meet hz_to_midi and midi_to_hz now. Part 1 depends on them.
Ends with: one melody, its retrograde, and its inversion, played in sequence.

3. Time is beats, not seconds

20 min
  • sleep 1 means one beat. use_bpm decides what a beat costs in seconds.
  • Run the same score at 60, 96, and 152 BPM and notice which tempo makes it sound like a different piece.
  • Sonic Pi's scheduler keeps timing exact regardless of how long our code takes to run. Trust it.
Checkpoint: we can write, hear, and re-time a short phrase without looking anything up.

Part 1. Why sound has structure

Physics before convention. Four lessons that explain where the twelve notes came from, so nothing later has to be taken on faith.

Harmonic series, ratios, temperament

4. One note is many notes

30 min
  • Build a tone by adding sine partials at 1f, 2f, 3f, 4f with falling amplitude. Add them one at a time and listen.
  • The partials we just stacked are the harmonic series. Every pitched instrument produces some version of it.
  • Change the amplitude profile and hear timbre change while pitch stays put.
Ends with: an additive tone that fades from thin to rich as partials enter.

5. Consonance is small whole numbers

30 min
  • Play 220 Hz against 440, 330, 293.3, and 311. Rate each pair for smoothness before reading any labels.
  • The smooth ones are 2:1, 3:2, and 4:3. The rough ones have large numbers in their ratios.
  • Detune one partner by a few hertz and hear the beating that gives the game away.
Ends with: a ratio explorer that takes a fraction and plays it.

6. Twelve notes, one compromise

30 min
  • Stack pure 3:2 fifths twelve times. We land near seven octaves and miss by an audible margin.
  • Equal temperament divides the octave into twelve equal ratios of 21/12 and spreads that error everywhere.
  • Play a just major third against an equal-tempered one. The difference is small, real, and audible once we know to listen for it.
Ends with: the same triad in just intonation and equal temperament, back to back.

7. The envelope is the instrument

25 min
  • Hold pitch and synth constant. Vary attack, decay, sustain, release.
  • A slow attack turns a piano into a string section. A short release turns a pad into a percussion hit.
  • Envelope is how we encode staccato, legato, and accent later, so build the vocabulary now.
Checkpoint: given a recorded note, we can guess its rough envelope shape and reproduce it.

Part 2. Pitch space

The keyboard, the octave, and note spelling. Ends with a scale that makes anything we play sound deliberate.

musictheory.net

8. Twelve pitch classes

25 min
  • Walk 60 to 72 one semitone at a time and hear the octave close.
  • The keyboard's uneven black-key pattern is not decoration. It encodes where the semitone steps fall.
  • Pitch class is pitch modulo 12. Write the function, then use it to find every C in a range.
Ends with: a chromatic browser driven by one integer offset.

9. Octaves as address space

20 min
  • Play the same phrase at :c2, :c4, and :c6. Two of them will sound wrong for the material.
  • Register is an arrangement decision. Bass, melody, and inner voices occupy different bands for a reason.
  • Find the register where each Sonic Pi synth sounds best. Keep notes.
Ends with: one phrase spread across three registers with three synths.

10. Sharps, flats, and why spelling is not sound

25 min
  • F♯ and G♭ are the same key and the same integer. They are different names for different musical jobs.
  • Sonic Pi accepts :fs4 and :gb4 and gives 66 for both. Our transcriptions need the name as well as the number.
  • Carry a second field for spelling from now on. Part 8 depends on it.
Ends with: a pitch-class to spelling table and a note that prints both forms.

11. Pentatonic: the scale with no wrong notes

30 min
  • Five notes per octave, no semitone clashes, nothing that can sound like a mistake.
  • Take a random walk through scale(:e3, :minor_pentatonic, num_octaves: 2) over a held drone.
  • Constrain step size and repeat probability. Watch a random sequence turn into something that sounds composed.
Ear drill: play a random note in a one-octave window, hum it, then search up or down until they match. Ten trials, log the errors.

Part 3. Rhythm and meter

Timing is where beginners hear the biggest gains, and it needs no pitch knowledge at all. Six lessons.

Note values and meter

12. Durations as fractions

25 min
  • Quarter note is 1 beat, eighth is 0.5, sixteenth is 0.25. The names are historical, the arithmetic is not.
  • Encode a rhythm as a bare duration array and play it on one drum sound.
  • Clap along with the click while the pattern plays. Notice which durations we cannot yet feel.
Ends with: a rhythm interpreter that takes durations and any percussion sample.

13. Bars, and the accent that makes meter audible

30 min
  • Group eight identical eighth notes as 4/4, then as 3/4, using amplitude alone. Same notes, different piece.
  • 6/8 versus 3/4 is the same six eighths grouped 2×3 or 3×2. Hear it before naming it.
  • Write an assertion that a bar's durations sum to what the time signature promises.
Ends with: one pattern that flips between three meters at the press of Run.

14. Rests, dots, and ties

25 min
  • A rest is an event with no attack. Model it explicitly so bar sums stay checkable.
  • A dot adds half the value: 1.5, 0.75, 3. That is all a dot has ever meant.
  • A tie is one long event crossing a barline. Not two attacks. The difference is audible and it is what makes rhythm feel human.
Ends with: a phrase whose silence and tied note carry as much weight as the notes.

15. Syncopation on a grid

30 min
  • Build a 16-slot boolean bar. Fill the strong beats and listen. It sounds like a metronome.
  • Move accents to the offbeats. Anticipate a downbeat by one sixteenth. Listen again.
  • Encode one traditional clave pattern as a bit array and hear why it has outlived every genre that used it.
Ends with: three rhythmic variants of one pitch sequence, from square to funky.

16. Swing and microtiming

30 min
  • Delay every second eighth note by a fraction of its length. Sweep the fraction from 0 to 0.33 and hear straight become swung.
  • Add a few milliseconds of random jitter to onsets and amplitudes. Machines become players.
  • Overdo both. Finding the point where it collapses teaches more than finding the point where it works.
Ear drill: Sonic Pi plays a four-beat pattern, we clap it back, then reveal the durations. Start with two distinct values.

17. Tuplets and 3 against 2

30 min
  • Three events in the space of two: sleep 2.0/3. No visual guesswork required.
  • Run a 2-subdivision loop and a 3-subdivision loop against each other in separate threads.
  • Slow the tempo until both are followable, then speed up until they fuse into one pattern.
Checkpoint: a stable 3-against-2 texture that does not drift over sixteen bars.

Part 4. Intervals

The unit of melodic and harmonic distance. Three lessons, then a drill we keep using for months.

Interval exercises

18. An interval carries two measurements

30 min
  • Size comes from letter names, quality comes from semitone count. C to E is a third and it is major.
  • This is why C♯ to E and D♭ to E sound identical and are named differently. Spelling again.
  • Write interval_name(a, b) taking spellings as input and returning size plus quality.
Ends with: an interval namer tested against every pair in an octave.

19. The interval sound dictionary

30 min
  • Play each interval melodically, then harmonically. They feel like different things and we treat them as such.
  • Describe each one in our own words before learning the standard label. That description sticks better.
  • Anchor the hard ones to tunes we already know, and write the anchors in the file as comments.
Ends with: a personal reference file mapping each interval to a sound and an anchor.

20. Build our own drill harness

30 min
  • Random root, random interval from a configurable set, pause, then reveal by playing the answer named.
  • Weight the set toward the intervals we keep missing. That is the whole point of writing it ourselves.
  • Reuse the harness in Parts 5 and 6 for scales, chords, and cadences.
Ear drill: ten intervals a day, ascending only, from a set of four. Add a fifth interval after 9 of 10 twice running.

Part 5. Scales and keys

Where notes acquire jobs. Tonic, leading tone, and the reason a melody sounds finished.

Scales and key signatures

21. The major scale is a step formula

25 min
  • 2 2 1 2 2 2 1. Generate the scale from a root and that array. No memorising note lists.
  • Check the generator against scale(:c4, :major) for every one of the twelve roots.
  • Play the scale up, down, and in thirds. The pattern in thirds is a workout and it sounds good.
Ends with: a scale constructor verified against Sonic Pi in all twelve keys.

22. Scale degrees and the pull toward home

30 min
  • Hold a drone on the tonic. Play each degree above it and rate how badly it wants to move.
  • Degree 7 pulls hard to 8. Degree 4 leans to 3. Degree 5 is stable and not home.
  • End the same melody on four different degrees. Only one of them sounds like an ending.
Ends with: one phrase with four endings, ranked by how finished they sound.

23. The minor family

30 min
  • Natural minor is the major formula rotated. Harmonic minor raises degree 7 to restore the pull to the tonic.
  • Melodic minor changes on the way up and back on the way down, for reasons audible in one bar.
  • Diff the three as integer arrays and confirm the difference is one or two elements.
Ends with: the same eight-bar tune in all three minors, plus a printed diff.

24. Modes over a drone

30 min
  • Rotating the major step formula gives seven modes. That is the entire mechanism.
  • Hold a drone on one root and play all seven against it. The drone is what makes the difference obvious.
  • Identify the one altered degree that gives each mode its character. Dorian's sixth, Mixolydian's seventh, Lydian's fourth.
Ear drill: drone plus a random mode, we name it. Start with major, Dorian, and Mixolydian only.

25. The circle of fifths as a data structure

30 min
  • Generate it: start at C, add 7 semitones, take modulo 12, repeat. Twelve steps and we are home.
  • Adjacent keys share six of seven notes. That fact drives modulation, chord progressions, and key signatures.
  • Derive the sharp and flat counts for every key from the circle instead of memorising a chart.
Checkpoint: given any key, we can name its scale, its relative minor, and its two nearest neighbours without a lookup table.

Part 6. Chords and harmony

Stacked intervals, then the grammar that governs how they follow each other. The densest part of the course.

Sonic Pi chords · Harmony

26. Triads as stacked thirds

30 min
  • Root, plus 4 or 3, plus 3 or 4. Four combinations, four qualities, no exceptions.
  • Build all four from offsets and check against chord(:c4, :major).
  • Play each as a block and as an arpeggio. The arpeggio is easier to hear and harder to forget.
Ends with: a chord-quality trainer built on the Part 4 harness.

27. Inversions and voicing

30 min
  • Move the lowest note up an octave. Same pitch classes, different bass, different weight.
  • Spread a triad over two octaves and hear it open up. Close voicings sit, open voicings breathe.
  • Write invert(chord, n) and voice_near(chord, previous).
Ends with: a four-chord loop where nothing leaps, generated by our voicing function.

28. Diatonic chords and Roman numerals

35 min
  • Take every other degree of a scale. Seven triads fall out, and their qualities are fixed by the scale.
  • Roman numerals name a chord by its job rather than its pitch. That makes a progression key-independent data.
  • Render [:I, :V, :vi, :IV] in four keys from one symbolic list.
Ends with: a progression engine that takes numerals and a key and returns notes.

29. Cadences are punctuation

30 min
  • V to I is a full stop. IV to I is softer. Ending on V is a comma. V to vi is the sentence that swerves.
  • Play all four at the end of one identical eight-bar phrase.
  • Name them once they are distinguishable by ear, and no sooner.
Ear drill: random cadence at the end of a fixed phrase, we name the type. Four options.

30. Seventh chords and tension

30 min
  • Add a fourth note. Compare major 7, minor 7, dominant 7, and half-diminished on one root.
  • The dominant seventh contains a tritone, and that tritone is what makes it demand resolution.
  • Resolve V7 to I in four voices and follow each voice individually.
Ends with: a V7 to I resolution audible voice by voice with a solo flag.

31. Voice leading as an optimisation problem

35 min
  • Represent a progression as four independent lines rather than a list of chords.
  • Minimise total movement, keep common tones, avoid crossing. It is a small search problem with musical constraints.
  • Play a naive root-position version and the optimised version back to back. The difference is not subtle.
Checkpoint: we can hear four separate lines inside a chord progression and mute any one of them.

Part 7. Melody, phrase, and form

From note sequences to musical sentences and paragraphs. Six lessons on structure above the bar.

Phrases and cadences

32. Contour and rhythm are separable

30 min
  • Reduce a melody to up, down, same. Play the contour on a fixed rhythm.
  • Play the original rhythm on a fixed pitch. Ask someone which version they recognise.
  • Rhythm usually wins. That result shapes how we approach transcription in Part 9.
Ends with: three controlled mutations of one tune and a verdict on what carries identity.

33. Motive, sequence, and development

30 min
  • A motive is a short idea that survives transformation. Transpose, invert, augment, fragment.
  • A sequence repeats a motive at a new pitch level. Two repetitions convince, four bore.
  • Build a sixteen-bar melody from one three-note cell and nothing else.
Ends with: a melody generated entirely from transformations of a single cell.

34. Question and answer

25 min
  • Four bars that end unresolved, four bars that close. Most tunes we know are built this way.
  • Change only the last two notes of the first phrase and watch the pair stop working.
  • Connect this to cadences. The answer phrase ends with the full stop from Lesson 29.
Ends with: an eight-bar period that sounds complete on its own.

35. Chord tones and decoration

30 min
  • Strip a melody down to notes that belong to the underlying chord. What remains is the skeleton.
  • The removed notes have names: passing, neighbour, suspension, anticipation. Each has a characteristic sound.
  • Put them back one category at a time and hear the line acquire direction.
Ends with: a melody, its harmonic reduction, and the two played in alternation.

36. Notated versus played

30 min
  • Add amp, articulation, and an onset offset to our event schema.
  • Render one phrase legato, detached, accented, and shaped with a crescendo to its high point.
  • A perfectly quantised performance of a good melody can sound worse than a sloppy one. Worth confirming firsthand.
Ends with: two renderers over the same score: score-strict and performance-shaped.

37. Form as control flow

30 min
  • Sections are functions. ABA is a call sequence. A varied return is a call with different arguments.
  • Keep literal repeats separate from varied ones in the data. The distinction is the whole art of form.
  • Assemble a two-minute piece from four sections and a transition.
Checkpoint: a piece long enough to have a shape, with no copy-pasted score data anywhere in it.

Part 8. Reading notation

The staff arrives now, when it is a decoding problem we already have the concepts for. Four lessons.

Staff, clefs, key signatures

38. Treble clef as a coordinate system

25 min
  • Vertical position maps to letter name. One line-to-space step is one diatonic step, not one semitone.
  • That last distinction is where most self-taught readers go wrong. Settle it early.
  • Translate eight printed notes into Sonic Pi symbols and play them.
Ends with: a one-octave treble cheat sheet, handwritten or generated.

39. Bass clef and the grand staff

25 min
  • Same system, different offset. Learn it as a constant added to the treble mapping.
  • Middle C sits between the staves and belongs to both.
  • Encode a simple two-hand keyboard texture as two voices in our event model.
Ends with: an eight-bar bass-and-melody sketch read from a printed grand staff.

40. Key signatures as defaults

30 min
  • A key signature is a default rule applied to every matching letter until overridden.
  • An accidental is a local override that expires at the end of the bar. This is scoping, and scoping we know.
  • Write the resolver: letter plus key signature plus local accidentals in, MIDI number out.
Ends with: a small resolver we reuse in every transcription from here on.

41. Decode four printed bars

35 min
  • Read in this order: time signature, key signature, rhythm, pitches, ties, articulation.
  • Enter the whole thing as data before picking a synth. Sound design is a distraction at this stage.
  • Run the bar-sum check, then listen and compare against a recording.
Checkpoint: four bars read from notation and playing correctly, with no MIDI file involved.

Part 9. Transcription

A repeatable workflow for turning a score or a recording into code we can inspect and test. Five lessons.

IMSLP · Mutopia

42. Finding music we can legally use

25 min
  • IMSLP for scans, Mutopia for typeset public-domain scores, MuseScore for community arrangements with varying licences.
  • Public domain rules differ by country and a modern edition of an old work can carry its own copyright.
  • Build a shortlist of twenty pieces at our level and record the source and licence for each one.
Ends with: a sources.md file with twenty candidates, each with a link and a licence note.

43. The four-pass pipeline

30 min
  • Pass 1: tempo, meter, phrase boundaries. Pass 2: rhythm only. Pass 3: contour and anchor pitches. Pass 4: exact pitches and expression.
  • Never skip forward. Every pass we skip gets paid for twice in debugging.
  • Mark uncertain notes with a comment convention we can grep for.
Ends with: a checklist and an event schema we apply unchanged to every transcription.

44. Transcribe by ear

35 min
  • Find the tonic first by humming a note that feels like home, then locate it on the keyboard.
  • Work in intervals from the anchor rather than guessing absolute pitches.
  • Sixteen bars of a familiar monophonic melody. Slow the recording if needed.
Ear drill: four-note melodic dictation over a drone. Grow to six notes, then eight, then add rhythm.

45. Transcribe from a score

35 min
  • Pick a short piece from the Lesson 42 shortlist.
  • Encode pitch and duration exactly. Annotate with source measure numbers as comments.
  • Separate what the score says from what we think it should sound like. Keep both, clearly labelled.
Ends with: a score-faithful encoding with full provenance in comments.

46. Debug a transcription like software

30 min
  • Assert bar totals. Assert range. Flag leaps larger than an octave for manual review.
  • Loop a single suspicious bar against the source until the wrong one is obvious.
  • Most transcription errors are rhythmic, and most rhythmic errors are a missing tie.
Milestone: a 30 to 60 second melody with source reference, bar-by-bar data, validation helpers, and an expressive rendering.

Part 10. Texture and arrangement

Several things happening at once, on purpose. Concurrency we already understand, applied to voices.

Live loops, threads, sync, FX

47. Independent voices

35 min
  • live_loop and in_thread give one process per voice. sync and cue keep them aligned.
  • Sonic Pi's deterministic scheduling means voices do not drift. Verify this with a sixteen-bar test.
  • Keep each voice's score in its own data structure. Shared mutable state across voices is as bad here as anywhere.
Ends with: a two-part arrangement that loops indefinitely and stays locked.

48. Bass lines that outline harmony

30 min
  • Start with roots on downbeats. It works and it is dull.
  • Add approach notes a semitone below the next root. Add passing tones between roots a third apart.
  • Give the bass its own rhythm. A bass that copies the melody's rhythm is not a second voice.
Ends with: the same progression with a root bass and a walking bass, played in sequence.

49. Drum grids

30 min
  • One 16-step array per drum. Kick, snare, hats, and nothing else to begin with.
  • Accent with amplitude and shift hats slightly late to get the pocket we built in Lesson 16.
  • Transcribe a groove we like by repeated listening, one instrument at a time.
Ends with: a groove stored as readable arrays rather than an opaque loop.

50. Register, timbre, and space

35 min
  • Two voices in the same register and timbre will fight. Separate them by pitch band, envelope, or panning.
  • Use with_fx :reverb and :echo to place voices at different depths.
  • Fixing a muddy arrangement with volume alone almost never works. Try it and confirm.
Ends with: one harmonic skeleton arranged three ways: sparse, dense, and wide.

51. Canon and imitation

35 min
  • One melody, two voices, a delay between entries. The oldest trick in Western music and still the most satisfying to code.
  • Vary the delay and the transposition. Most combinations sound bad, which is the lesson.
  • A melody that works as a canon has to harmonise with itself. Find out what that constrains.
Checkpoint: a three-voice canon on a subject of our own that holds up for sixteen bars.

Part 11. Chromatic harmony

What happens when a piece leaves its key, and how to hear it coming. Three lessons.

Chord progressions

52. Secondary dominants

35 min
  • Treat any diatonic chord as a temporary tonic and put its own dominant in front of it.
  • V/V in C major is D major, which needs an F♯ that does not belong to the key. That accidental is the whole effect.
  • Play the diatonic progression and the tonicised version back to back.
Ends with: an eight-bar progression with one clearly audible tonicisation.

53. Modulation as state change

35 min
  • Hold the current key in a variable. Roman numerals become relative addresses against it.
  • A pivot chord is a chord that is valid in both keys, so it can be reinterpreted mid-progression.
  • Move to the dominant, sit there for four bars, then come home. Note the moment our ear accepts the new tonic.
Ends with: a passage that changes key twice and returns.

54. Borrowed chords and the blues

30 min
  • Take a chord from the parallel minor and drop it into a major key. Minor iv is the classic.
  • The twelve-bar blues uses dominant sevenths where theory says it should not, and it works anyway.
  • Encode a twelve-bar blues in numerals and render it in three keys.
Checkpoint: given a progression with one chromatic chord, we can say where it came from.

Part 12. Capstones

Four projects. Faithful representation first, expressive realisation second.

Our own sources and our own library

55. Capstone A: solo melody

60+ min
  • 32 to 64 bars from the shortlist.
  • Pitches, rhythm, articulation, dynamics, and phrase marks, all as data.
  • Keep measure references and a list of the passages we are unsure about.
Deliverable: a faithful monophonic transcription plus an expressive renderer.

56. Capstone B: melody and accompaniment

90+ min
  • A short song, hymn, or keyboard miniature.
  • Melody, bass, and inner harmony as three separate structures with one shared timeline.
  • Every bar validated for metric integrity, every chord checked against the sounding notes.
Deliverable: a structured multi-part score, not one long script.

57. Capstone C: two-voice polyphony

120+ min
  • A two-voice invention, canon, or contrapuntal excerpt.
  • Encode the voices independently and verify their alignment automatically.
  • Annotate motives, imitative entries, cadences, and the implied harmony.
Deliverable: two voices, independently inspectable, that reproduce the source together.

58. Refactor into our own library

60+ min
  • Extract the helpers written more than twice: playback, validation, transposition, voicing, articulation.
  • Settle on one event schema and migrate old pieces to it.
  • Keep it small. A framework large enough to hide the score has failed.
  • Write a README that explains the representation choices to us in six months.
Final checkpoint: we can take a printed score or a short recording and turn it into structured, editable code, and explain the theory encoded in it.

Folk tune, hymn melody, simple classical theme, or a motif we can legally work from.
Level 2
Melody with chordal accompaniment, a short piano miniature, or a lead sheet.
Level 3
Two-part counterpoint, a four-part chorale, or a carefully reduced orchestral passage.

Working rhythm

Four sessions a week covers the 58-lesson spine in about fifteen weeks, with the capstones after that. The mix that works:

SessionLengthWhat
Two per week25–35 minNew lessons in order.
One per week30 minConsolidation. Reread the last four lessons and rebuild one example from memory.
One per week30 minFree play. Use only what we have learned so far and make something we like.
Most days10 minEar drills from our own drills.rb.

Every fourth week, add no new theory. Finish a transcription instead. Theory sticks when we use it under pressure, and the pressure comes from wanting the thing to sound right.

The progression of representations

Our code passes through these stages. Each one is the right answer for a while and then stops being it.

# 1. Imperative. Fine for four notes, unmanageable for forty.
play :c4
sleep 1
play :e4
sleep 1

# 2. Parallel arrays. One index desync away from disaster.
notes = [:c4, :e4]
durs  = [1, 1]

# 3. Event records. Now fields can be added without breaking anything.
score = [
  {note: :c4, dur: 1, amp: 0.8},
  {note: :e4, dur: 1, amp: 0.6}
]

# 4. Named voices sharing a timeline.
piece = {
  melody: [...],
  bass:   [...],
  chords: [...]
}

# 5. Symbolic harmony, realised on demand.
progression = [
  {degree: 1, quality: :major, beats: 4},
  {degree: 5, quality: :dom7,  beats: 4}
]
# ...rendered into voices by a function that knows the key.

Stages 3 to 5 are conventions of this course. The primitives come from Sonic Pi. Official tutorial.
